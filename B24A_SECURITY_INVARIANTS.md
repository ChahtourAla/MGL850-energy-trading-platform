# B24-A1 security invariant map

- Historical authority: `inspectHistoricalHour`, B22 `reconcile`, and `verifyCandidatePlan` verify archived B22 evidence and all allocations before the B23 commitment is rebuilt. Tests use real B22 ingestion/matching and reject a draft plan and a tampered manifest.
- Authentication: `b24_approver` inserts fixture policies/deployments; `b24_evaluator` is a separate non-owner login. Triggers derive approver from `session_user`. Tests deny evaluator policy/deployment writes, B22 mutations, wallet ciphertext reads, evidence writes and trigger disabling.
- Spending: only `SIMULATED_TEST` policies and `TEST_FIXTURE` deployments in the marked disposable database are accepted. Policy/deployment rows are locked; database trigger checks scope, status, expiration and budget. Existing reservations count against limits.
- Uniqueness: database unique allocation identity applies across deployments, and `(deploymentId,buyerAddress,nonce)` is unique. Reservation rows are immutable; uncertain reservations are never released automatically.
- Exact terms: B21 arithmetic requires 28 Wh at 90750 to equal 2541 base units and zero remainder; B23 typed-data helper builds an unsigned digest. SQL checks the recorded unsigned term fields against the allocation and deployment. PostgreSQL does not recompute Keccak, so future signing must independently revalidate.
- Limits: no real consent, signing, token allowance, transfer, settlement intent or chain evidence exists. The synthetic fixture does not prove a live Hedera deployment or actual physical delivery. The local database owner remains trusted.

- Replay eligibility: existing immutable reservations are rechecked against the current fixture deployment, policy status, scope, budget and authorization deadline. Expired, revoked or retired records stay reserved for accounting and are not returned as currently eligible. `inspectReservation` exposes history without asserting eligibility. Authenticated PostgreSQL integration tests verify unchanged reservation, nonce, settlement identity and budget after each blocked retry.
- Signing boundary: B24-B must independently revalidate current policy status and scope, policy and deadline expiration, deployment activation, complete authoritative plan and commitment, EIP-712 domain and digest, and reservation identity, nonce and deadline. A stored reservation is not a signing authorization.
