# B24 offline test evidence

Branch `feature/b24-complete-wallet-security`, accepted baseline `949059db28095ff343e1bff72b1f3a0509fbd04b`. Node v22.20.0 was available; the backend declares >=22.22.3. The mismatch remains. All PostgreSQL containers were newly created and labeled by the repository harnesses; all chain operations were on local in-process Hardhat instances with synthetic users and policies.

- `powershell -NoProfile -ExecutionPolicy Bypass -File tools/b24-wallet-bound-postgres.ps1`: **1 Mocha integration test passed** on a fresh disposable PostgreSQL 17 database with 41 migrations. It covers the genuine two-market B22 fixture, authenticated B24 roles, exact 2,541-unit allocation, registered buyer signing, funding, allowance, canonical receipt verification, readiness and local B23 settlement. Two separate sessions were observed waiting on PostgreSQL locks for duplicate funding and allowance requests; a different market sharing the funding budget was blocked. Concurrent conflicting allowance reduction and a second market sharing the same buyer/token/spender were rejected while approval was unresolved, and readiness for the second market also returned unresolved.
- The same integration injects loss of the submission response and the subsequent unresolved-event write for both mint and approval. It recovers the already mined transactions by reserved sender and nonce, checks one operation per identity, and does not rebroadcast. It also covers lost receipt recovery after policy revocation and deployment retirement, invalid signature/readiness data, wrong caller/minter/spender and sender nonce, small funding cap, excessive allowance, nonce uniqueness, protected tables, replay rejection, session tampering, and a local chain revert. A deliberately stalled local minter timed out, left an unresolved journal and was not called a second time on retry.
- `powershell -NoProfile -ExecutionPolicy Bypass -File tools/b21-run-postgres-tests.ps1`: passed on retry with 39 migrations; schema/migration diff reported no difference and representative legacy fixture records remained unchanged. An earlier run found a Prisma foreign-key declaration mismatch, corrected before the passing run; another attempt hit PostgreSQL's transient startup shutdown.

Remaining verification limits: the suite does not exhaustively model every provider hang, crash point, malicious trusted verifier behavior, or all token/block reorderings. The funding budget is deliberately scoped by buyer/token/minter. The signer, fixture approver, local RPC provider and receipt verifier are trusted; this is not verified live custody or real consent.
