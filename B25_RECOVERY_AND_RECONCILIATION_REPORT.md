A prepared attempt stores the exact transaction hash before any broadcast. Repeated execution returns that existing identity and does not broadcast again. The verifier's recovery service queries the original hash, verifies the actual transaction and receipt and records evidence when valid. Missing receipt or RPC errors remain unresolved. A local block mismatch produces an append-only noncanonical observation; existing verified evidence remains historical and the intent is no longer confirmed. A read-only market report rechecks local canonicality before counting recorded evidence.

A controlled conflicting operator nonce is detected and recorded. Separate application processes now test interruption after durable preparation, after committed handoff, after broadcast, and immediately after confirmation evidence commits. A fresh verifier recovers without the original operator wallet; the original nonce remains reserved. The verifier and RPC provider remain trusted; a malicious provider can misrepresent chain data. A canonically verified local status-0 receipt is recorded as immutable negative evidence and reported as failed/unpaid. A noncanonical negative receipt is preserved and becomes unresolved. The trusted verifier can assert evidence in SQL and must itself be protected; the database cannot prove RPC data independently. A local confirmation is not Hedera finality.

The committed database handoff is the authorization boundary. A delayed provider can still broadcast after a later revocation; it is an already-handed-off transaction, not a cancelled one. The local test delays the actual send past timeout, commits revocation, releases the provider and confirms one payment. A lost handoff commit response remains HANDOFF_UNKNOWN and is never automatically rebroadcast. A mined conflicting operator nonce is recorded as NONCE_CONFLICT and remains unresolved.

The suite now injects transient failures into `getNetwork`, `getTransaction`, `getTransactionReceipt` and block retrieval, verifies unresolved results without deleting confirmation evidence, then verifies recovery after the provider is restored. A separate loopback-only Hardhat process remains running across application restarts; preparation, handoff, broadcast and post-evidence interruption paths were exercised. The enumerated RPC failure cases and their test commands are listed in the acceptance matrix.

The additive B25 outcome journal records serialized verifier-authenticated success, revert and noncanonical observations without modifying historical evidence. Disposable tests exercised both success-to-revert and revert-to-success for the same signed transaction after local reorganization; the fixture performs remine, never the recovery service. Current reporting independently checks chain evidence. The verifier and RPC are trusted; local results are not Hedera finality. The acceptance matrix records the executed local tests.

If an RPC returns no block at a height the current head says should exist, recovery returns `CANONICAL_BLOCK_UNAVAILABLE` without appending a noncanonical event. A shorter current chain or a different valid hash is handled as noncanonical. The read-only recovery scan uses timeouts and a deadline; it does not broadcast.
