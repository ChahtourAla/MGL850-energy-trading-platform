# B26 scheduler and recovery design

A bounded continuous scheduler scans aligned UTC intervals oldest first, with a finalization grace period. A database uniqueness constraint identifies an interval and approved configuration. The B26 worker authenticates through a dedicated disposable PostgreSQL role, claims a timed lease, and updates checkpoints only with its current fencing token. Runs and control requests have append-only audit events. Missing source data is deferred; an invalid snapshot or nonpayable draft is blocked with automatic retry disabled. An authenticated administrative recovery request may re-enable a blocked run without changing financial evidence.

The worker invokes B22 historical verification and matching through the B22 role. Payment preparation uses independently authenticated B24 evaluator, signer, funder, allowance and receipt roles, an enrolled ephemeral wallet registry and an approved local-chain session. B25 creates the intent, prepares the signed transaction and records a durable handoff. B26's additive database triggers lock and check the current B26 fence at B25 attempt creation and handoff. They do not hold a database transaction across Python or RPC. After a committed handoff, revocation or lease expiry cannot retract an in-flight transaction.

B25 verifier-backed reconciliation supplies a report. PostgreSQL checks complete allocation membership, amounts and recorded B25 outcome identities, but cannot itself verify blockchain canonicality. The authenticated verifier and local RPC are trusted. A settled run must be rechecked; a noncanonical receipt becomes unresolved and is never counted as paid. A raw stored run or API response is not live financial proof.

The accelerated clock is available only through the authenticated marker-protected disposable worker and cannot move into the future. The standalone entrypoint does not construct or restore signer custody; the service-backed local integration supplies fixture-owned ephemeral registries. Process restart after a committed handoff or mined broadcast is tested without recreating the original keys, but unattended provisioning for new unsigned allocations after a full signer-process restart remains unresolved.
