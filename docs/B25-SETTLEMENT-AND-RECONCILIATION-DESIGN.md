The authoritative market, immutable allocation, B24 reservation and signed terms remain the sources of financial facts. `V2SettlementIntent` remains unique per allocation. For the disposable chain only, a versioned B25 fixture intent ID separates the database identity from the EIP-712 digest without redefining B21's chain-296 ID. `B25LocalIntentBinding` binds the reservation, session and digest to that intent.

The B25 migration permits chain 31337 only in the specifically named disposable database; existing chain 296 behavior remains. Runtime SQL functions additionally require a marker and an authenticated role. Intent and attempt identities are immutable. The B21 settlement-attempt record is created with the same UUID as the B25 local attempt. The operator nonce, calldata hash and signed transaction hash are committed before broadcast. A later request observes the attempt and does not rebroadcast. The handoff authorization locks policy and deployment and inserts an immutable B25DispatchHandoff row. Its database commit is the linearization point. A revocation or retirement committed first blocks a new handoff. Once the handoff commits, the provider may send even if a timeout or a subsequent revocation occurs; neither event cancels the in-flight payment. A lost handoff response is treated as unknown, never as proof of cancellation. The signed transaction is not a live payment authorization.

A separately authenticated verifier checks receipt and events using the registered provider and session, then records B21 evidence and a B25 chain-session binding. PostgreSQL does not independently verify blockchain receipts; the verifier and local provider are trusted. A recovered noncanonical block appends an observation and changes the intent to `UNKNOWN`; historical evidence is retained. Reports count a recorded payment only after current receipt verification.

The current recovery path handles the recorded transaction hash and never issues a replacement. It detects a mined conflicting sender/nonce transaction with a bounded canonical-block scan and records an immutable observation. Separate-process tests cover interruption after preparation, handoff, broadcast and evidence persistence; the enumerated RPC failure cases are recorded in the acceptance matrix. The acceptance matrix records the executed reorganization and adversarial scenarios and their test boundaries. Full production finality, real customer consent and Hedera execution are not implemented.

A local status-0 receipt is accepted as negative evidence only after checking session, sender, nonce, target, signed calldata, canonical block, absence of logs and on-chain paid state. The separately authenticated verifier writes immutable `B25RevertEvidence`, and the intent and attempt become `REVERTED`. Reconciliation independently rechecks that receipt before reporting failure; loss of canonicality appends an observation and returns the status to `UNKNOWN`.

The additive B25 outcome journal records serialized verifier-authenticated success, revert and noncanonical observations without modifying historical evidence. Disposable tests exercised both success-to-revert and revert-to-success for the same signed transaction after local reorganization; the fixture performs remine, never the recovery service. Current reporting independently checks chain evidence. The verifier and RPC are trusted; local results are not Hedera finality. The final acceptance matrix records 106 PASS, 0 FAIL and 0 NOT RUN.

Executor-side read-only chain checks and transaction preparation have bounded waits. A timeout before attempt creation leaves no attempt; a timeout after committed handoff remains unresolved because it does not cancel an already-handed-off broadcast.
